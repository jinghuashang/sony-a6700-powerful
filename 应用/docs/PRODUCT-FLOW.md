# 桌面应用流程与交互约定

最终交付是内置运行环境的 macOS 桌面应用。dev19 交互改版使用三步状态条：**操作前须知 → 准备并连接 → 功能管理**。默认演示模式，使用合成数据；相机模式复用真实 USB 服务与事务逻辑。环境检查、人工声明、固件预检分别呈现。

## 三步主流程

| 阶段 | 页面与用户动作 | 服务端约束 |
|---|---|---|
| 操作前须知 | 机型范围、设备／数据风险、保修及免责声明直接可见；本机检查自动运行，组件详情和验证范围按需展开。阅读确认后“开始准备相机” | 本机检查未通过、未阅读或服务未就绪时不能继续；阅读确认不是写入授权或合同接受 |
| 准备并连接 | 一页展示 FTP 条件处理、MSC、自动关机／电量、最后接线。每项显示菜单路径，右侧常驻显示相机界面右上角关键项小卡；下方一次声明“以上设置已完成，相机已连接并保持开机”，再连接检查 | `confirm_preparation` 只接受布尔值，在准备阶段且环境、阅读均通过时设置四个稳定准备 ID；不枚举或访问 USB，不能覆盖环境失败或固件兼容性 |
| 功能管理 | 检查成功直接进入，不再弹重复结果确认。功能列表每项同时显示状态、选择和依赖；右侧先选解锁／关闭，再列出实际需修改的功能及数量 | 默认选中未解锁项；状态已符合的不重复写入；空选择、未知字段、守卫不匹配、未满足依赖仍由共用执行器拒绝 |

须知与准备阶段的主按钮固定在底部，滚动长文不会遮住下一步。右上角随时可复看须知，复看不改变会话状态。“返回”回到须知；“重新连接”先结束原会话，清除准备声明及兼容性，再回到准备页，不能直接继续写入。

没有 FTP 菜单是正常情况，不需要去寻找或开启它；如已有且开启，关闭传输后重启释放介质占用。日常 USB 管理只使用普通数据线，Pico 救砖接线属于独立流程。菜单路径与示意来源由 `preparation.py` 提供，图解只保留右上角关键项并标记“非实机截图”。

## 功能管理

功能管理页保留一个功能列表，不在设备卡片和操作面板里重复列状态。选中项和将改变的项区别显示；“选择未解锁”“选择可关闭”“全选／清空”只改变选择，不会连带发起写入。功能级依赖由服务端清单声明；当前开放项之间没有字段依赖，最终判断仍在执行器。

桌面暂时隐藏备份与恢复：没有独立页签、“更多工具”入口或占位按钮，主界面只展示解锁和关闭。待完整备份恢复实现并验证后再设计入口。原有稀疏备份恢复核心、开发者命令、测试及用户备份文件保留；本次不新增完整备份、自动备份或历史撤销。写入前记录和事务保护不变。

## 执行与结果

- 发出操作后立即锁定模式、选择及重复操作；关窗和正常退出仍受繁忙状态保护。
- 进度页优先显示当前阶段和实际经过时间，过程记录折叠展示，不估计百分比或剩余时间。
- 取消按钮只发出一次请求，随后显示“正在等待结果”；不会强制终止已发送写入，也不会自动重发。
- 成功、无需修改后自动回到工作区，并保留本次结果提示；不需要再点“返回主页”。
- 失败、内容不兼容、回退及结果不确定分别展示原因和下一步。原始错误、写入尝试标记与过程放入“诊断详情”。不确定结果不包装成成功，也不提供一键重复写入。

## 演示与相机模式

页眉始终明确当前模式。演示默认使用六项合成功能，不代表完整实机功能验证；实际相机功能列表由正式清单与当前读取决定。演示场景、断连与重连收进右上角“演示设置”，切换场景会使阅读、准备和兼容状态失效。忙碌期间不能切换模式或场景。

切换到相机模式仅做本机启动检查；真正连接检查才可能请求系统管理员授权、接管接口、认证并上传临时读取程序。因此只读预检不是“相机文件系统完全零写入”。只有所选功能的显式执行按钮才发起对应写入操作。

## 共用服务与贡献边界

`preparation.py` 仍维护 `ftp_stopped`、`camera_msc`、`power_awake`、`usb_connection` 四个准备 ID。单次人工声明不会跨启动持久化，CLI 的逐项确认保持不变。每次设备操作继续使用相同设备锁、当前内容预检、写前记录和回读逻辑。

UI 不实现补丁、地址或固件规则。模块入口见 [AI 代码地图](AI-CONTEXT.md)，构建与测试见 [桌面应用说明](DESKTOP-PREVIEW.md)，备份边界见 [功能状态备份与恢复](BACKUP-RESTORE.md)。
