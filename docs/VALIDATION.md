## 历史实机路线

- Pico PIO 开漏 v2、GP28 经 470Ω 到相机侧 D− 已完成过 RAM 程序加载。
- AP-only 只读 RAM 程序在设置 GPIO17 bit16 HIGH 后，历史实机已有 USB 枚举、eMMC 初始化、分区表和读取记录。
- 2026-10-19，操作者确认 USB-A 持续供电、先拔测试板再移动数据线的简化流程可用。
- 同次原自动会话直接记录了低基线检查和 45/45 条发送，但其 USB 等待曾超时；后续用户成功确认单独保存，不将原失败日志改写成自动成功，也不宣称已证明所有扩展坞均兼容。
- 这些是原研究版本的证据；本仓库新整理的主机实现没有在本轮重新上机。

## 本轮离线核对

- 10 个无设备单元测试通过：记录长度／CRC／顺序／边界、未知载荷拒绝、基线已 HIGH 阻断、上电超时释放、完整流只发送一次、ACK 失败不重发、串口分片与错误版本、USB 身份不符不查表、命令白名单与异常 DATA 拒绝。
- 使用公开适配器和固定本地上游重建 RAM 程序，产物 20,992 字节，SHA-256 与历史程序 `8d8b9689…` 一致；禁止的存储写入／执行符号未链接。
- 生成的 Pico v2 sketch 与历史源码逐字节一致，SHA-256 为 `acc13bfc…`；PIO 与生成头保持上游原样。本轮没有重编译 UF2／刷入 Pico。
- 新记录编码器生成的 45 条记录与历史 `records.json` 逐条一致；拼接流 SHA-256：`219fb83e0e6681a6b54783c0928c77a513c7fb03b4769843b3aeb1ba35356fc5`。
- 默认入口对该载荷离线校验通过，没有打开串口／USB。
- 发布文件清单仅含自有文本代码、文档、许可与上游哈希；不包含厂商固件、ROM、第三方二进制、个人数据或研究日志。

本地 RAM 重建使用 Apple clang 及 AArch64 GNU binutils；其他工具链的逐字节复现尚未验证。仓库附 GitHub Actions 配置，初次远端运行状态应以仓库 Actions 为准，本记录不将本地测试冒充远端运行。

## 尚未验证／未发布

- 本轮未连接相机、重刷 Pico、重新注入或写相机非易失存储。
- Linux／Windows 实机连接、多机型、多固件版本、Pico 2 和所有 USB 扩展坞组合未验证。
- 原始用户区分区表已知范围的双读，不等于已覆盖完整物理 eMMC；完整备份／全盘恢复未作为本批完成项，也不开发或宣称已验证这些模块。
