# 基础原理

## 两条通路

本批公开的是硬件冷启动通路：电脑通过 USB 串口控制 Pico，Pico 将特殊载波和串行记录送入相机 BootROM，BootROM 将程序写到片上 RAM 后跳转。RAM 程序初始化 USB，再以 Fastboot 协议与电脑通信。

```mermaid
flowchart LR
    H[电脑主机代码] -->|USB 串口| P[RP2040 Pico PIO/DMA]
    P -->|GP28 开漏 经 470Ω 接 D−| B[相机 BootROM]
    B -->|记录写入及跳转| R[片上 RAM 只读程序]
    R -->|换普通 USB 数据线后| F[Fastboot 身份与分区表查询]
```

另有从相机正常系统进入维护服务的普通 USB 通路。本批不发布这一通路，也不把其相机模式设置与 Pico 冷启动接线混在一起。Pico 通路无需先在菜单里寻找 MSC／FTP 设置。

## 三层协议

1. **电脑 ↔ Pico**：115200 的 USB 串口设置；数据帧为 `command:u8 + length:u16le + body`。Pico 返回同样结构，ACK=`0x81`、错误=`0x82`。115200 不是相机引导信号的速率。
2. **Pico → 相机**：PIO/DMA 驱动 GP28，使用 48 kbit/s 的专用载波／串行发送。记录中的每个字节包含起始位、8 位数据、奇校验及停止位；开漏通过切换输出方向在拉低／释放之间切换，不能简单用普通串口线替代。相机串行接收实测位于 USB2 D−，并非 SBU A8/B8。
3. **RAM 程序 ↔ 电脑**：USB VID:PID=`18d1:4ee0`、接口 `ff/42/03`、bulk OUT=`01`、IN=`81`。设备返回 `INFO`、`OKAY`、`FAIL` 等 Fastboot 标签；必须另查 `getvar:product`，仅 VID/PID 不足以证明是本项目的程序。

## BootROM 记录

所有整数为小端：

| 字段 | 长度 | 含义 |
|---|---:|---|
| length | 4 字节 | 头部与数据的长度，包含这 4 字节、不含末尾 CRC |
| kind | 2 字节 | 命令类型 |
| value | 4 字节 | RAM 地址、入口或协议常量 |
| data | 可变 | RAM 数据 |
| CRC32 | 4 字节 | 前述整个 body 的 CRC32 |

发送顺序为：空的 `0x0123` 起始标记 → 每块最多 512 字节的 `kind=1` RAM 数据 → `0xffff` 设置入口 → `0` 设置协议解锁常量 → 再次发送 `0x0123` 结束。载荷固定装入／进入 `0xfe020000`；本批实现限制在从该地址开始的 64 KiB 窗口。已验证载荷为 20,992 字节，分为 41 块，因此共 45 条记录。

`0x2cf25621` 是本条路线使用的协议常量，已用于历史实机加载；不是机身唯一的密钥，也不是本仓库提供的存储解密密钥。源码没有实现上游的栈覆盖解锁分支。

## A6700 适配与只读边界

固定上游原面向 A7 IV 的程序；A6700 适配在 AP 启动过程中设置 GPIO17 bit16 为 HIGH，切到可用的 USB2 DP/DM 路由，并省去 CP bring-up。接线实测与 USB 枚举／读取共同支持这条路线，不推广为其他机型的通用接法。

RAM 程序的命令分发只保留 `getvar`、分区表／指定只读 dump 和 `upload`。构建检查要求最终链接符号中没有 `mmc_write_blocks`、`cmd_flash`、`cmd_download`、`cmd_exec`、`cmd_poke` 和 CP bring-up。部分不可达旧函数仍可能出现在本地生成的 C 文本中，以最终链接和分发可达性为边界。

本仓库主机查询入口进一步只允许身份、版本和分区表，不提供 dump 或全盘备份。这里“只读”指不向相机非易失存储写入；进入过程仍会向相机 RAM 装入程序，并改变临时硬件状态。断电后 RAM 程序丢失。
