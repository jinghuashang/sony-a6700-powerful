# Fastboot 备份与固件刷写

先完成[进入 Fastboot](进入Fastboot.md)并核对身份。本页公开底层读写通路，不提供固件、私人镜像或一键恢复；完整物理 eMMC 备份／全盘恢复的覆盖和闭环未验收。

## 必须分清的镜像

| 对象 | 意义 | 本项目原始读写版 |
|---|---|---|
| `nflasha` | 用户区原始字节，范围来自分区表下限，包含密文与表 | 可原样备份；实验版可原样刷写 |
| `nflashaB0`／`nflashaB1` | eMMC 两个硬件引导区的原始字节 | 可备份已知窗口；实验版可刷写 |
| `nflasha15` 等逻辑分区 | 解密视图／特定逻辑分区，不同于整片原始字节 | 不接受其 dump／flash |
| Sony 官方更新程序、DAT／EXE 升级包 | 升级容器，不是原始分区镜像 | 不能直接刷入 |

原始读写版没有机身密钥或存储解密密钥，不将逻辑明文自动加密。请使用自己目标设备、相同区域且来源明确的原始镜像；仅凭文件名或大小相同，不能证明可互换。原始镜像可能含机身资料，**不要上传到仓库或公开 issue**。

## 指定区间备份

默认只读载荷即可读取。Python入口使用十进制或 `0x` 前缀的数，单位为512字节扇区，每次最多32768扇区（16MiB）：

```sh
# 引导区0前4MiB：两次独立读取一致后才保存
python 脚本/备份扇区.py --目标 nflashaB0 --扇区数 0x2000 \
  --输出 备份/引导区0-前4MiB.raw --双读校验

# 引导区1前4MiB
python 脚本/备份扇区.py --目标 nflashaB1 --扇区数 0x2000 \
  --输出 备份/引导区1-前4MiB.raw --双读校验

# 用户区起始16MiB，仍只是一个区间
python 脚本/备份扇区.py --目标 nflasha --起始扇区 0 --扇区数 0x8000 \
  --输出 备份/用户区-起始16MiB.raw --双读校验
```

脚本先核对载荷身份，再查询表初始化 eMMC，随后 staging／upload；总长度、末尾 OKAY、可选双读均通过后才保存。同名输出不覆盖，打印 SHA-256 供后续核对。不会把区间备份称作全盘备份，也不自动合并／恢复大镜像。

若相机加载的是原始读写版，上述命令须加 `--模式 原始读写`。

## 标准 Fastboot 命令

也可以使用 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) 的 `fastboot`，先检查设备与 product。电脑上只保留本次目标 Fastboot 设备。

```sh
fastboot devices
fastboot getvar product
fastboot getvar version
# 确认 product 是当前载荷后：
fastboot oem partition

# 这里的 offset/count 均为十六进制扇区：2000 = 8192扇区 = 4MiB
fastboot oem partition dump nflashaB0 0 2000
fastboot get_staged 备份/引导区0-前4MiB.raw
```

通用 CLI 可能覆盖既有输出，运行前自己选择新的文件名；若需要自动防覆盖和双读，用前面的 Python 入口。

上游协议也支持省略范围导出整个分区表覆盖的用户区：

```sh
fastboot oem partition dump nflasha
fastboot get_staged 备份/用户区-分区表范围.raw
```

这仍是分区表给出的下限，不代表已核对 EXT_CSD 的完整物理容量。历史原始读取按区间完成，本轮没有重新验收一次长传输、全盘备份或恢复管理；长传输可能受供电／连接／RAM运行时长影响。

## 原始镜像刷写（实验版）

只读载荷主动拒绝 `download`／`flash`。先显式构建并注入原始读写版，查询 product 必须为 `A6700-AP-raw-maintenance`；随后独立执行刷写。该版保留上游 raw／Android sparse 写入器，限制目标仅为三个原始别名，拒绝未按512字节对齐的普通镜像，不提供 `erase`、`poke`、`exec` 或重启命令。

以下是通路命令示例，不是已实机验证的恢复流程；“本机原始镜像”必须替换为自己已核对区域与哈希的镜像，不是本项目提供的下载：

```sh
fastboot getvar product
# 仅当明确返回 A6700-AP-raw-maintenance 后继续
fastboot oem partition

# -S 512K 对应RAM程序的512KiB下载缓冲，大镜像由CLI拆成sparse传输
fastboot -S 512K flash nflasha 备份/本机用户区原始镜像.raw

# 确有引导区恢复需求、镜像区域已核对时才分别使用
fastboot -S 512K flash nflashaB0 备份/本机引导区0原始镜像.raw
fastboot -S 512K flash nflashaB1 备份/本机引导区1原始镜像.raw
```

刷写会从目标起点写入，写多少取决于镜像／sparse记录；不能用一个中间区间的备份直接对整个 `nflasha` 执行 flash，否则偏移不对。CLI 的 OKAY 不代替独立回读比较，也不证明重启后的功能正常。任何通信不确定或写入失败都不自动重发；本批没有事务回退或一键回官方固件的承诺。

刷写完成后应另行读取同一区域并核对完整字节／哈希，再按[接线页](接线与操作.md)退出。当前维护者**没有对这份新原始读写载荷执行实机 flash／重启／恢复验收**；此前固定FTP／快门补丁的实机记录不能移用到它。
